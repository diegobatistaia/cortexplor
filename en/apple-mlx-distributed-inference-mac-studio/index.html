Apple's MLX Update Runs an 816-Billion-Parameter Model on Macs

A new version of the framework uses an RDMA link over Thunderbolt to pool several Mac Studios and run models too large for a single machine.

Newsroom Cortexplor Based on 1 source

Apple has released a new version of MLX, its open-source framework for running and training AI models on its own chips, adding support for distributed inference across multiple Mac Studio computers. The company says a cluster of four Mac Studios can run Muse Spark Open, a model with nearly 816 billion parameters (the internal numbers a model tunes during training), at more than 36 tokens per second — the units of text a model processes — above average human reading speed.

The feature rests on two recent releases: a low-latency RDMA driver over Thunderbolt 5 — RDMA lets one machine read another's memory directly, bypassing its processor — introduced in macOS 26.2, and new MLX communication collectives called "jaccl" that use that driver to split work between machines. Apple says its test setup linked two Mac Studios with two Thunderbolt cables to double the connection's bandwidth.

Apple benchmarked three open-weight models — Muse Spark Open (816 billion parameters), Mistral Medium 3.5 (128 billion) and Qwen 3.8 (27 billion) — comparing its latest Mac Studio chip, the M5 Ultra, against the previous generation, the M3 Ultra.

The two smaller models fit on a single Mac Studio with 512GB of unified memory even at a 65,536-token context window — the amount of text a model processes at once: Qwen 3.8 uses up to 68GB and Mistral Medium 3.5 up to 158GB, according to Apple.

Muse Spark Open is different. At its native precision (BF16), the nearly 816-billion-parameter model would need more than 1.6TB of memory. Compressed to 4 bits (the NVFP4 format), it drops to about 493GB — still too much for one machine once the memory needed during generation is added. Apple instead splits the model across two or more Mac Studios using a technique called pipeline parallelism: one machine processes the first half of the model's layers and sends the result to a second machine, which handles the rest.

What the M5 chip changes

According to Apple, time to first token — how long before the model starts answering — is up to 4.6 times faster on the M5 Ultra than on the M3 Ultra, thanks to Neural Accelerators, dedicated matrix-multiplication hardware inside the GPU. Generation speed, which depends on memory bandwidth, is 1.6 times higher on the M5 Ultra: 1.2 TB/s versus the M3 Ultra's 819 GB/s.

Peak power draw is about 200W for the M3 Ultra setup and 300W for the M5 Ultra setup during inference — a fraction of what a toaster uses, by Apple's own comparison.

For developers, Apple published the MLX LM package used in the benchmarks, along with the mlx.launch command, which starts the same program across multiple machines at once, selecting the new RDMA-based communication collective with the --backend jaccl flag.

The release matters beyond the benchmark numbers it reports. It gives developers a way to run frontier-scale open-weight models without renting cloud GPU capacity, provided they already own enough Mac Studio hardware — a path AI teams have mostly reserved for data-center chips until now.

In practice

  • Who can use it: anyone with one or more Mac Studios running M3 Ultra or M5 Ultra chips and Apple's free, open-source MLX framework.
  • Since when: the new MLX release and the macOS 26.2 RDMA driver came out this week, according to Apple.
  • Cost: MLX itself is free; the cost is the hardware — a Mac Studio with up to 512GB of unified memory.
  • What changes: running a model with nearly 816 billion parameters used to require cloud infrastructure; Apple now shows it running locally by splitting the work across Mac Studios linked over Thunderbolt.

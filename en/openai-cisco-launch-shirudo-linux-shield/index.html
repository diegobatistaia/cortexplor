OpenAI and Cisco Launch Shirudo to Shield Linux Servers

The open-source tool uses eBPF to block an exploit without rebooting the system, buying time until a permanent patch ships.

Newsroom Cortexplor Checked against 3 sources

OpenAI and Cisco launched Shirudo on Monday, an open-source runtime that shields running Linux systems from an exploit while security teams prepare a permanent fix, according to an OpenAI announcement corroborated by SiliconANGLE and TechRadar.

The name is Japanese for "shield." It targets a familiar problem in infrastructure security: building and rolling out a patch can take days or weeks, and taking a vulnerable service offline in the meantime is not always possible without hurting the business that depends on it, OpenAI said.

Shirudo relies on eBPF, a Linux technology that lets small, verified programs run inside the operating system itself without a reboot. Using it, the tool watches a service's behavior and applies a temporary barrier, called a "shield," that blocks only the specific action an attacker is exploiting while legitimate traffic keeps flowing, according to OpenAI and TechRadar.

TechRadar notes that security flaws fall into two broad categories: "zero-day" bugs, unknown to the vendor until they are exploited, and "n-day" bugs, already known but still unpatched. Shirudo is built for that second group, offering a temporary safeguard while the permanent patch is still being prepared.

In a controlled test, the two companies used Codex, OpenAI's coding agent, to automatically generate a shield against a vulnerability dubbed Java4Shell in a live Elasticsearch service. The shield blocked the exploit attempt without the service needing a restart, according to OpenAI and SiliconANGLE.

Every shield Shirudo creates is cryptographically signed and checked by Linux's own eBPF verifier before it loads, and the system logs that check in a hardware component called a Trusted Platform Module (TPM), so a security team can later prove what was blocked and when, OpenAI said.

The companies say the project exists because AI-driven attacks can now find and exploit flaws within seconds, making traditional manual defense too slow, Cisco's security engineering lead, Thomas Graf, told SiliconANGLE. "There is nothing more important than giving security teams the tools they need to match the speed of the AI-driven threats they are facing," Cisco chief product officer Jeetu Patel told SiliconANGLE.

According to SiliconANGLE, Graf said the average time to exploitation has already turned negative: a growing share of vulnerabilities are now attacked before they are even publicly disclosed, which makes waiting weeks for a traditional patch untenable.

The two companies' longer-term goal, per SiliconANGLE, is to rebuild IT infrastructure with security built in from the start: systems that can automatically roll back to a known-good state after an attack and that use reinforcement-learning techniques to test their own defenses against unknown threats.

"When one team finds a better way to protect a system, others shouldn't have to start from scratch," OpenAI co-founder and president Greg Brockman told SiliconANGLE.

In practice

  • Who can use it: any developer, security researcher or Linux infrastructure operator, for free, according to OpenAI.
  • Since when: available as of November 23, 2026.
  • What it costs: nothing. The code is licensed under BSD 2-Clause, and the eBPF programs under a dual BSD/GPL license, OpenAI said.
  • How to try it: OpenAI published a VM quickstart guide and a hands-on lab built with Isovalent; a technical webinar on the project is scheduled for December 15.
  • Who is affected: teams running production Linux systems, such as databases and web services, according to OpenAI.

According to SiliconANGLE, Shirudo is the first project to come out of a broader infrastructure-security partnership between the two companies. The code is on GitHub, and OpenAI and Cisco are inviting developers and security researchers to contribute new shields and improvements.

The release lands as AI-generated exploits move faster than the traditional patch cycle most enterprises still rely on, a gap that has pushed several large software and cloud vendors to experiment with kernel-level, machine-speed defenses over the past year.
